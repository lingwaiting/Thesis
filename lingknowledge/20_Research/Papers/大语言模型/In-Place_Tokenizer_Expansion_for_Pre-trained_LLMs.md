## 摘要翻译

### 中文翻译
分词器在预训练开始时固定分配词汇表以匹配预训练语料库的分布，反映了当时的部署优先级。当这些优先级发生变化时，后来添加的语言每个词被分割成更多 token，可能提高这些语言用户的延迟、计算和能耗。云端模型可以负担广泛的词汇表，但对于端侧模型，嵌入矩阵和 LM-Head 矩阵占每 token 解码带宽的重要份额。本文提出 Tokenizer Expansion，一种"原地"升级预训练模型分词器的方案。我们在多语言语料库上继续现有分词器的 BPE 合并，使大多数源 token 保持不变作为单个 token，每个新 token 有精确的源子 token 分解。我们将保留的嵌入行原样复制，将新行初始化为其源子 token 嵌入的均值。两阶段适应（仅嵌入训练，然后全模型继续预训练）恢复源检查点质量。我们在 LFM2-8B-A1B（8B MoE 模型）的继续预训练检查点上应用该方案，帮助生成带 128K 分词器的 LFM2.5-8B-A1B。扩展的分词器编码印地语和越南语的 token 数比源分词器减少约 2.4× 和 2.6×（泰语高达 4.0×），估计每字符解码速度提升 2.2-3.7×。

## 研究背景与动机

### 领域现状
大语言模型的分词器通常在预训练开始时就固定下来，之后不再更改。分词器的词汇表分配与预训练语料库的语言分布成正比。当模型需要服务新语言用户时，语言被添加得越晚，token 化效率越低——单词被分割成更多子词 token。

### 现有方法的局限性
- **重新预训练**：成本极高，不适合已经投入生产的模型
- **云端 vs 端侧差异**：云端模型可以负担大词汇表（嵌入矩阵占比较小），但端侧模型必须使用小词汇表来控制每 token 解码带宽
- **碎片化问题**：小词汇表导致非主要语言的文本被过度碎片化

### 研究动机
如何在不重新预训练的情况下，升级已有 LLM 的分词器以支持新语言，同时保持模型质量和推理效率？

## 方法概述

### 核心方法

**1. BPE 延续合并**
- 在已有 BPE 分词器基础上，用多语言语料库继续合并操作
- 大多数源 token 作为单个 token 保持不变
- 每个新 token 有精确的源子 token 分解

**2. 嵌入初始化策略**
- 保留的嵌入行直接复制
- 新行的嵌入初始化为其源子 token 嵌入的均值
- 这保证了初始化就接近合理的语义表示

**3. 两阶段适应**
- 阶段一：仅训练嵌入层（embedding-only training），快速适应新词汇表
- 阶段二：全模型继续预训练（full-model continued pre-training），恢复整体质量

### 关键创新
- **原地升级**：无需重新预训练，直接在已有检查点上操作
- **无损迁移**：源 token 完全不受影响，新 token 的嵌入有自然的初始化
- **可逆分解**：新 token 可以精确分解为已知的源子 token，便于调试和验证
- **工程实践**：公开报告了负面发现（negative findings），对工业部署有重要参考价值

## 深度分析

### 研究价值
- **理论贡献**：提出了一套完整的"原地"分词器扩展方法论，包括 BPE 延续、嵌入初始化和两阶段适应
- **实际应用**：对端侧 LLM 部署有直接价值，可显著降低低资源语言用户的推理成本
- **领域影响**：为模型生命周期管理提供了新范式——分词器不再是不可变的

### 优势
- 工程实用性极强，直接降低多语言场景的推理成本
- 方法简洁清晰，易于复现
- 公开权重和分词器，有开源精神
- 报告负面发现，对社区负责

### 局限性
- 目前仅在 Liquid AI 的 LFM 系列模型上验证
- 扩展的语言数量有限（印地语、越南语、泰语）
- 两阶段适应仍需要计算资源
- 对新语言的效果因语言形态特征而异

### 适用场景
- 端侧 LLM 需要支持新语言但无法重新预训练
- 多语言部署的推理成本优化
- 开源模型的社区语言扩展

## 技术路线定位

本文属于 **LLM 基础设施与部署优化** 技术路线，主要关注**分词器升级与多语言支持**子方向。与传统的重新预训练路线不同，本文提出的"原地"升级方法填补了模型生命周期管理中的重要空白。

## 未来工作建议

1. 扩展到更多语言系列（如 CJK、阿拉伯语等）
2. 探索单阶段适应（跳过仅嵌入训练阶段）
3. 将方法应用于更多模型架构（Dense、MoE 以外）
4. 研究分词器扩展对长文本生成质量的影响
