## 摘要翻译

### 中文翻译
LLM 越来越有能力回答关于企业级文档集合的复杂问题，但评测很困难：公司不愿共享内部通信，而合成数据集又过于简单。作者提出 **CorporateBench (CB)**，一个人工验证的多任务问答基准，其规模接近 LLM 在企业通信网络中遇到的条件，评测语料超过 **23 万篇文档**。

CB 通过四家合成企业（规模从 12 到 10,000 名员工）在两个维度上评测 LLM：信息抽取（information extraction）与知识库查询（knowledge base querying）。每个语料都从一个**随时间演化的知识库**中采样而来，该知识库描述了一个一致的世界，从而保证跨文档的逻辑一致性——即便在数十万篇文档的规模下也是如此。作者在 CB 上评测了五个 LLM，发现随着输入规模接近真实尺度，模型性能持续下降。CB 为 LLM 开发者提供了面向企业通信推理的评测指标，填补了评测生态中的一个关键空白。

### 核心要点提炼
- **研究背景**：企业级长文档问答缺乏大规模、可控、逻辑一致的评测基准。
- **研究动机**：真实企业数据难获取、合成数据太简单，需要一个规模真实且逻辑自洽的基准。
- **核心方法**：从"时态知识库"采样生成 23 万+ 文档、四个合成企业、两维度（抽取 + 知识库查询）的问答基准。
- **主要结果**：五个 LLM 在规模逼近真实时性能持续下降。
- **研究意义**：填补企业通信推理评测空白，为长上下文 LLM 提供压力测试工具。

## 研究背景与动机

### 领域现状
长上下文 LLM 与 RAG 系统被广泛用于企业文档问答，但评测面临两难：真实企业数据因隐私不可得，合成数据又常因规模小、逻辑不一致而失真。

### 现有方法的局限性
- 真实数据：受隐私限制，无法共享。
- 合成数据：规模小、任务单一，且常缺乏跨文档的逻辑一致性，无法还原真实企业通信网络的复杂度。

### 研究动机
作者希望构建一个**规模真实（数十万文档）+ 逻辑自洽（时态知识库保证一致性）** 的企业问答基准，为长上下文与检索增强系统提供可信的评测标尺。

## 研究问题

### 核心研究问题
1. 如何生成规模接近真实、逻辑跨文档一致的企业文档语料？
2. 如何系统评测 LLM 在信息抽取与知识库查询两个维度上的表现？
3. 模型性能如何随输入规模演化？是否存在规模化失效？

## 方法概述

### 核心思想
用一个**随时间演化的知识库（temporal knowledge base）** 作为"世界模型"，从中采样生成 23 万+ 篇企业文档，保证跨文档逻辑一致；再围绕这些文档构造两个维度的问答任务，评测模型在真实规模下的表现。

### 方法框架

#### 整体架构

![[page1_fig1.png|600]]

> 图1：CorporateBench 的整体框架。从时态知识库出发，生成四家规模不同的合成企业语料，并据此构造信息抽取与知识库查询两类问答任务。

1. **时态知识库建模**：定义一个随时间演化、逻辑一致的企业世界。
2. **文档采样生成**：从知识库采样生成 23 万+ 篇文档，构成四家合成企业（12~10,000 员工）。
3. **任务构造**：围绕信息抽取与知识库查询两个维度生成问答对。
4. **多模型评测**：在五个 LLM 上评测，考察性能随输入规模的变化。

> 图2：不同方法在问答任务上的结果对比，展示信息抽取与知识库查询两维度的表现差异。

### 关键创新
1. **时态知识库驱动的生成**——保证数十万篇文档间的跨文档逻辑一致性。
2. **规模真实性**——语料达 23 万+ 文档，逼近企业通信网络的实际条件。
3. **双维度评测**——同时覆盖信息抽取与知识库查询，且经人工验证。

## 实验结果

### 主要结果

![[qa_results_by_model_page1.png|600]]

> 图3：五个 LLM 在 CorporateBench 上的表现随输入规模的变化，显示规模逼近真实尺度时性能持续下降。

- **规模化失效**：五个 LLM 在输入规模接近真实尺度时性能持续下降。
- **双维度差异**：信息抽取与知识库查询两个维度的难易与失效模式不同。
- **一致性保障**：时态知识库保证跨文档逻辑一致，使评测结果可信、可复现。

## 深度分析

### 研究价值
- **理论贡献**：提出"时态知识库 → 大规模一致语料"的生成范式，为长上下文评测提供方法论。
- **实际应用**：可作为企业 RAG/长上下文 LLM 系统的压力测试与选型标尺。
- **领域影响**：填补企业通信推理评测的关键空白。

### 优势
- 规模真实、逻辑自洽，解决了合成数据的核心痛点。
- 双维度 + 人工验证，评测质量有保障。
- 规模化失效的发现对产业界有直接警示意义。

### 局限性
- 合成数据虽逻辑一致，但与真实企业的"噪声、格式多样性"仍有差距。
- 主要覆盖问答，对企业文档的其他任务（摘要、结构化提取等）覆盖有限。
- 五个 LLM 的评测配置细节（上下文截断、检索策略）可能影响结论外推。

### 适用场景
- 企业级 RAG 系统的评测与选型。
- 长上下文 LLM 的能力边界研究。

## 与相关论文对比

- 相比早期小型合成 QA 基准（如 HotpotQA 的合成变体），CB 在规模（23 万+）与跨文档一致性上显著更强。
- 相比真实企业基准（不可公开），CB 提供了可复现、可共享的替代方案。

## 技术路线定位

本文属于**长上下文评测 × RAG**技术路线，主要关注企业级大规模文档问答的基准构建，是"合成数据走向真实"的代表工作。

## 未来工作建议

1. 引入更丰富的文档类型与真实企业噪声（邮件、表格、图表等）。
2. 扩展任务类型（摘要、信息抽取、多跳推理等）。
3. 探索规模化失效的成因（上下文长度、检索召回、推理能力），并给出缓解方案。

- 23 万+ 文档规模逼近真实，是难得的大规模可控基准。
