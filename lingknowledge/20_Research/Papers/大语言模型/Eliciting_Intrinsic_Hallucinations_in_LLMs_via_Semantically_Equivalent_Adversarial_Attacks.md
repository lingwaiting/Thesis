# Eliciting Intrinsic Hallucinations in LLMs via Semantically Equivalent Adversarial Attacks

## 摘要翻译

### 中文翻译
LLM 常与外部知识源结合使用（如 RAG）以提高事实准确性并减少幻觉。然而，这些系统仍易受内生幻觉影响——模型生成不忠实于检索证据的虚假信息。我们提出一种新框架，通过对抗优化方法找到自然、语义等价的查询变体，对模型进行压力测试以评估其对此现象的鲁棒性。我们将该框架（强制严格语义等价约束和内生幻觉目标）应用于白盒、灰盒和黑盒对抗攻击技术。在 5 个开源和 5 个闭源生成模型、3 个数据集上的评估表明，即使最先进的模型也对保义扰动高度敏感，忠实性显著下降（GPT-5-mini 下降高达 50%）。我们的发现表明，在最先进的 LLM 中，对上下文证据的忠实使用仍然脆弱，这促使我们需要不依赖于表面查询形式的鲁棒架构和训练目标。

### 核心要点提炼
- **研究背景**：RAG 系统被广泛用于减少幻觉，但内生幻觉（不忠实于检索证据）问题仍未被充分研究
- **研究动机**：RAG 的忠实性可能在语义等价的查询扰动下被破坏——这在安全关键应用中尤为危险
- **核心方法**：对抗优化 + 严格语义等价约束 + 内生幻觉目标，覆盖白盒/灰盒/黑盒攻击
- **主要结果**：10 个模型在 3 个数据集上均表现出脆弱性，GPT-5-mini 忠实性下降高达 50%
- **研究意义**：首次系统揭示 RAG 忠实性对输入表面形式的脆弱依赖

## 研究背景与动机

### 领域现状
RAG 被广泛部署以提升 LLM 的事实准确性。然而，现有工作主要关注"外生幻觉"（模型自身知识缺陷），对"内生幻觉"（模型忽略或曲解检索到的正确证据）关注不足。

### 现有方法的局限性
- RAG 的忠实性评估通常仅在标准查询上测试
- 缺乏对语义等价但表面形式不同的查询的系统性鲁棒性测试
- 现有对抗攻击方法往往生成语义漂移的扰动，无法严格测试"保义"场景下的忠实性

### 研究动机
在安全关键应用（医疗、法律、金融）中，RAG 系统不仅需要准确，还需要在查询的微小变化下保持对证据的忠实性。本工作提出通过语义等价对抗攻击来压力测试这一能力。

## 方法概述

### 核心思想
通过对抗优化生成语义等价但能诱发内生幻觉的查询变体，系统评估 LLM 在 RAG 场景下对检索证据的忠实性鲁棒性。

### 方法框架

![[Paper_motivation_v2.png|800]]

> 图1：方法动机示意——语义等价的查询扰动如何导致 RAG 系统产生内生幻觉（输出与检索证据不一致的内容）。

#### 三个关键组件
1. **语义等价约束**：确保生成的对抗查询与原始查询在语义上等价（使用语义相似度阈值）
2. **内生幻觉目标**：优化查询以最大化模型输出与检索证据之间的不一致性
3. **多攻击范式**：
   - **白盒攻击**：完全访问模型梯度和内部表示
   - **灰盒攻击**：仅访问模型输出 logits
   - **黑盒攻击**：仅访问模型生成的文本输出

#### 评估设置
- **5 个开源模型 + 5 个闭源模型**：包括 GPT-5-mini、Claude 系列等
- **3 个数据集**：覆盖不同领域的 RAG 场景
- **评估指标**：上下文忠实性（contextual faithfulness）下降幅度

## 实验结果

### 主要结果

#### 整体脆弱性
- 所有 10 个模型在 3 个数据集上均表现出对语义等价对抗攻击的显著脆弱性
- GPT-5-mini 的忠实性下降高达 50%
- 即使最先进的闭源模型也无法完全抵御此类攻击

#### 攻击范式对比
- 白盒攻击效果最强（可访问梯度优化）
- 黑盒攻击仍能造成显著性能下降（仅通过文本输出来优化）
- 这表明脆弱性不依赖于攻击者对模型的深度访问——即使是文本级攻击也有效

#### 模型鲁棒性差异
- 闭源大模型通常比开源小模型更鲁棒，但差距并不巨大
- 模型规模与鲁棒性之间没有简单的线性关系
- 部分模型的"过度自信"特征使其更容易在对抗条件下产生内生幻觉

## 深度分析

### 研究价值评估

#### 理论贡献
- **定义内生幻觉的对抗鲁棒性评估框架**：将幻觉研究从"是否存在"推进到"在什么条件下存在"
- **揭示忠实性的表面形式依赖性**：模型对检索证据的使用方式依赖于查询的表面措辞——这是基础性的脆弱性
- **语义等价约束的创新性使用**：确保攻击的"公平性"——不是通过改变语义来诱导幻觉，而是暴露模型在保义条件下的不一致性

#### 实际应用价值
- 为 RAG 系统的安全部署提供压力测试工具
- 指导 RAG 架构设计：需要不依赖于查询表面形式的鲁棒证据融合机制
- 对法律、医疗等安全关键领域的 RAG 部署具有直接警示意义

### 局限性分析

1. **对抗攻击的覆盖度**：攻击方法有限，可能存在更有效的攻击未被探索
2. **防御方法未讨论**：论文主要揭示问题，未提出解决方案
3. **真实世界场景的迁移**：对抗攻击在真实用户查询中的代表性问题
4. **评估指标的局限**：忠实性度量可能不完美反映真实的信息准确性

> [!tip] 关键启示
> RAG 系统对检索证据的忠实性可能是表面的——改变查询措辞而不改变语义，就能让模型"看到正确的证据但给出错误的答案"。这个发现对 RAG 的可靠性具有深层警示。
